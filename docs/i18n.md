# Internationalization

## Choice: next-intl

We use `next-intl` for locale routing and content localization with the App Router.

## Why next-intl

- First-class App Router support (Server and Client Components)
- Locale as a URL segment with typed, locale-aware navigation helpers
- Loads only the active locale's messages on the server - no bundle bloat

## URL contract

Set by `localePrefix: "as-needed"` in `src/i18n/routing.ts`: the default locale has no prefix, the others are prefixed.

| Path         | Result                  |
| ------------ | ----------------------- |
| `/`          | en (default, no prefix) |
| `/ru`        | ru                      |
| `/en`        | redirects to `/`        |
| unknown path | 404                     |

## Proxy

The middleware file convention was renamed to **`proxy`** in Next 16 (`src/proxy.ts`). Behavior is identical. Do not rename it back to `middleware.ts`.

## Navigation

src/i18n/navigation.ts - is a locale-aware Link / useRouter / usePathname

## Usage

### Server Component

```tsx
import { getTranslations, setRequestLocale } from "next-intl/server";

export default async function Page({
  params,
}: {
  params: Promise<{ locale: string }>;
}) {
  const { locale } = await params;
  setRequestLocale(locale); // required for static rendering

  const t = await getTranslations("HomePage");
  return <h1>{t("title")}</h1>;
}
```

### Client Component

```tsx
"use client";

import { useTranslations } from "next-intl";

export function Hero() {
  const t = useTranslations("HomePage");
  return <h1>{t("title")}</h1>;
}
```

## Rules

- Internal navigation: import `Link` / `useRouter` / `usePathname` from `@/i18n/navigation`, never from `next/link` or `next/navigation` — otherwise the locale prefix is lost.
- `usePathname` from `@/i18n/navigation` returns the path **without** the locale prefix.
- A new key goes under a namespace in **both** `messages/en.json` and `messages/ru.json`.
- Call `setRequestLocale(locale)` in every localized layout and page that should be statically rendered.
- Never hardcode a locale list — derive it from `routing.locales`.
